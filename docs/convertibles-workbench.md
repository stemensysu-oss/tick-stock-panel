# 可转债工作台

本页说明 `feature/funds-convertibles` 分支的可转债扩展。入口为 `/convertibles`；通过现有 L2 前后端扩展机制注册，基金研究仍使用 `/funds`。当前实现采用独立数据与计算模型，不抓取集思录页面、Cookie 或会员接口。

## 能做什么

- 在 28 个研究字段中选择显示列，按全部字段排序，按名称、代码、概念、行业、评级、证券类型、价格、溢价、双低、年限、规模和收益率组合筛选。
- 在本机浏览器维护自选、排除名单和显示列；同时比较最多 4 只转债；在价格与转股溢价率散点图中点选查看详情。
- 分别查看强赎观察、回售观察、下修记录和公告。价格条件与正式公告是两类信息，不互相替代。
- 在单只详情中维护日期现金流、全价/净价、应计利息、折现率、期权参数、观察条款、历史收盘价及公告记录。可以先试算，再保存。
- 通过 CSV 更新基础清单，通过有权限的 TickFlow Key 刷新清单内转债及已明确配对正股的报价。
- 导出当前筛选 CSV，或备份包含现金流、条款及公告的完整 JSON；恢复备份前必须校验、预览并确认整份替换。

生产页面初始为空，不内置演示行情。离线预览中的证券名称、价格、条款和公告均为虚构示例。

## 数据来源及目前的边界

| 数据 | 当前接入方式 | 仍需核对的内容 |
| --- | --- | --- |
| 转债和正股最新价格、涨跌幅、成交额、换手率 | TickFlow 报价适配器，或用户 CSV | Key 权限、覆盖证券、实际报价时间；配置成功不代表连通性已验证 |
| 正股配对、转股价、评级、行业、剩余本金、到期日、基金持仓 | 用户维护的 CSV | 发行人资料、转股价生效日、持仓报告及公告日期、统计覆盖范围 |
| 现金流、强赎/回售条款、观察价格 | 单只研究记录 | 完整现金流、逐日有效转股价、实际交易日、条款适用期 |
| 强赎、回售、下修及其他公告 | 单只研究记录及来源链接 | 公告原文、发布时间和是否已实施；系统不自动识别或判读公告 |
| 转股价值、溢价、双低、触发价、收益率、纯债/期权模型值 | 后端计算 | 输入完整性、价格时点、参数与计算口径 |

本扩展没有自动建立全市场正股配对及条款库；需先导入研究清单，再更新报价。没有声称已经接通集思录的数据或完整复刻其会员算法，也没有交易下单功能。真实行情是否可用，以本机使用有权限的 Key 后实际刷新结果为准。

TickFlow 适配复用原软件密钥与端点设置，新增页面不保存或返回密钥。可在设置的数据源页面配置。适配器使用既有官方 SDK，批量请求清单中的债券与正股，超时 20 秒，不自动重试；接口错误不会把供应商原始错误正文或认证数据传给前端。

官方契约依据：[TickFlow 实时行情](https://docs.tickflow.org/zh-hans/api-reference/实时行情/查询实时行情)、[TickFlow FAQ](https://docs.tickflow.org/zh-Hans/faq)。免费历史行情服务与有权限的实时行情服务不能互相等同。集思录功能研究仅作为字段及交互设计参考，相关数据获取须遵守各数据源授权和[集思录用户协议](https://www.jisilu.cn/account/agreement/)。

## 28 个显示字段

所有金融百分数使用 `20 = 20%` 的口径。金额在 API、CSV 和持久化中以人民币元表示；表格的亿元和万元仅为显示换算。转债按每张面值 100 元计算。

| 界面字段 | 内部字段 | 来源或计算 |
| --- | --- | --- |
| 代码 | `code` | 导入；按文本保留前导零 |
| 转债名称 | `name` | 导入 |
| 现价 | `bond_price` | 每张元；行情或导入 |
| 涨跌幅 | `bond_change_pct` | 百分数；行情或导入 |
| 正股代码 | `stock_code` | 明确配对，不由债券代码猜测 |
| 正股名称 | `stock_name` | 导入 |
| 正股价 | `stock_price` | 不复权元价格；行情或导入 |
| 正股涨跌 | `stock_change_pct` | 百分数；行情或导入 |
| 正股 PB | `stock_pb` | 导入；负 PB 合法 |
| 转股价 | `conversion_price` | 导入；须核对生效日 |
| 转股价值 | `conversion_value` | `100 × 正股价 ÷ 转股价` |
| 转股溢价率 | `conversion_premium_pct` | `(现价 ÷ 转股价值 − 1) × 100` |
| 双低值 | `double_low` | 现价 + 溢价率百分数 |
| 纯债价值 | `pure_bond_value` | 完整未来现金流按显式折现率折现的模型值 |
| 评级 | `credit_rating` | 导入；系统不据评级暗设折现率 |
| 期权价值 | `option_value` | 简化欧式转股期权模型，依赖显式参数 |
| 正股波动率 | `stock_volatility_pct` | 导入的年化波动率，保留窗口与复权方式 |
| 回售触发价 | `put_trigger_price` | 当前转股价 × 明确回售比例 |
| 强赎触发价 | `call_trigger_price` | 当前转股价 × 明确强赎比例 |
| 本金/流通市值 | `debt_to_float_cap_pct` | 剩余债券本金 ÷ 正股流通市值 × 100 |
| 基金持有 | `fund_holding_pct` | 所提供报告期的基金持有本金占剩余本金比例；非实时全量持仓 |
| 到期日期 | `maturity_date` | 导入，`YYYY-MM-DD` |
| 剩余年限 | `remaining_years` | 距到期日的自然日数 ÷ 365，下限 0 |
| 剩余规模 | `outstanding_amount` | 剩余本金；界面显示亿元，不是发行规模或交易市值 |
| 成交额 | `turnover_amount` | 行情或导入；界面显示万元 |
| 换手率 | `turnover_rate_pct` | 百分数；允许超过 100% |
| 到期税前收益 | `ytm_pct` | 完整日期现金流的 ACT/365 年复利 IRR |
| 回售情景收益 | `put_yield_pct` | 用户明确指定的回售现金流情景 IRR |

`debt_to_float_cap_pct` 使用的是上述明确的本金口径；没有把尚未确认的集思录列名视为可互换定义。期权价值也不是“交易价减去纯债价值”。

## 第一次使用

1. 打开「可转债工作台」，选择「导入 CSV」，下载空模板。至少填写 `code`、`name`，计算溢价和双低还需要债价、正股价和转股价。
2. 填写这批价格对应的数据日期。日期不是导入时间；历史研究不能把今天价格填作过去快照。
3. 预览数据并检查警告、换算单位及错误。确认后保存。任何一行错误都会阻止整批写入。
4. 点击转债名称进入详情，按实际资料填写现金流、条款和公告。选择「试算」查看计算结果，再「保存研究」。
5. 如已配置有权限的 TickFlow Key，选择「更新行情」。该操作只更新当前清单内的报价，不补造转股价、正股配对或公告。
6. 使用「备份研究」导出 JSON；需要回到既有研究状态时选择「恢复备份」，完成预览后确认。

“重新载入”只重新读取已保存清单；“更新行情”才会请求行情服务。

### CSV 约定

支持 UTF-8/BOM、逗号分隔，最多 2 MiB、2,000 条。英文字段与中文常用表头均可用。模板列出全部可导入标量字段，现金流和公告等嵌套研究数据不由 CSV 表达。

除 28 列中的原始输入外，模板还包括：行业、概念、证券类型、上市日期、正股流通市值、基金持仓报告期和公告日、触发比例、转股起始日、转股价生效日、波动率窗口与复权方式、债股报价时间、抓取时间、行情和条款来源及来源链接。

- `asset_type` 使用 `convertible` / `exchangeable`，或“可转债” / “可交换债”。省略时按可转债处理；需要明确区分的清单应填写此列。
- `volatility_adjustment` 使用 `none` / `forward` / `backward`，分别表示不复权、前复权、后复权。
- `quote_at`、`stock_quote_at`、`fetched_at` 使用含时区 ISO 时间，例如 `2026-10-21T15:00:00+08:00`。
- `outstanding_amount`、`turnover_amount`、`float_market_cap` 都以元输入；中文列“剩余规模(亿元)”“成交额(万元)”“流通市值(亿元)”会显式换算，并在预览中提示。不能凭数值大小猜测单位。
- 未知值留空，不用 0、100 或前值代替。派生计算列会忽略并重算。0 或负价格、NaN、无限值被拒绝；负涨跌、负 PB 和高换手可正常表达。
- 同一六位债券代码只能有一行，即使后缀写法不同也不允许重复。行情刷新另校验支持的沪深债券及明确正股代码族，不支持的标的返回错误，导入本身不证明真实资产类型。

**CSV 是清单替换，不是追加。** 对同代码的债券，已保存的研究记录会保留，并按新价格和新数据日重算；新 CSV 没包含的债券会被移出清单。若已有研究的证券类型或已知正股绑定改变，整批导入会被阻止，避免把另一标的的研究静默套入。请在移除记录前保存完整备份。

筛选 CSV 导出是当前选择字段的研究视图，未必包含所有重新导入所需的原始输入；它不是完整备份。文本单元格经过电子表格公式注入防护，代码列仍应按文本读取。

## 计算与观察的具体口径

### 日期现金流收益率

每一行现金流表示“某一天实际预计收到的每张税前总金额”。同一天的本金和利息要先合并为一行，系统不会再自动追加末期票息。

要计算到期收益率，须同时具备：

- 明确的全价；或净价加每张应计利息。全价已含应计利息，不能再加一次。
- 明确到期日、未来现金流及“已确认完整”的声明。
- 现金流末笔日期与到期日一致。

求解方程为 `全价成本 = Σ[现金流金额 / (1 + y)^(实际相隔天数/365)]`。只纳入计算日之后的金额；计算日当天的付款不假定买方仍能取得。实际实现以 `log(1+y)` 搜索，避免把较大的正收益率或接近 −100% 的负收益率错误判成无解。

结果为税前年有效收益率，不是到期利润的简单年化，也不是统一乘以 0.8 的税后收益率。这里没有声称与其他网站对短剩余期限采用的显示算法一致。

回售收益率另用用户输入并确认完整的 `put_cash_flows` 计算。这是情景分析，不会自动选择回售日，不会据此认定投资者具有实际回售权。

### 纯债和期权模型

纯债价值使用同一份已确认完整的到期现金流，以及明确填写、严格大于 −100% 的年折现率。评级不自动转换成固定折现率；模型值不代表保底兑付或交易底价。

期权价值使用欧式看涨期权的简化 B–S 模型，并乘以每张面值与转股价的换股比例。输入包括正股价、转股价、剩余期限、年化波动率、连续复利无风险利率及股息率。无风险利率和股息率没有自动默认值；零值需明确填写。波动率样本窗口或复权方式未填写时显示警告。

该模型未纳入发行人强赎、回售、下修、违约及交易摩擦等完整可转债结构，不能简单把“纯债 + 期权”当成可交易公允价格。

### 强赎与回售观察

每份条款明确填写窗口交易日数、需要命中的天数、价格比例、是否连续、适用起止日期。强赎按 `正股收盘价 ≥ 当日转股价 × 比例`，回售按严格小于判断。特殊条款的等号规则、余额触发、董事会裁量等不在这个价格窗口模型内。

已提供的到期日构成强赎和回售观察的上界：计算日到达或超过 `maturity_date` 时，价格观察状态为 `not_applicable`，即使没有另填条款结束日，也不会把已到期债券显示为当前条件达标。强赎观察还受已提供的转股起始日约束；条款起始日与转股起始日同时存在时，取较晚日期。

观察记录必须使用实际交易日、正股不复权收盘价和当天有效转股价。不能用自然日补齐，也不能把今日转股价套在全部历史上。当前支持最多 260 个观察点，不自动下载历史或重建转股价历史。

只有声明序列完整，并且 `observations_as_of` 与当前计算日一致，且覆盖整个窗口，才给出“满足价格条件”或“尚未满足”的状态。未确认完整、观察截止日落后、缺少适用期等情况保持未知/观察中。行情数据日更新后，旧观察声明自动失效。

`paused_until` 的含义是用户按条款设定的“暂停观察至该日，之后重新计数”，不是从任意“暂不强赎”公告文字自动推定的规则。必须按具体合同确认是否适用。连续模式统计窗口末尾连续命中数。

条件满足不会修改 `redemption_status`，也不会自动生成已决定强赎、可回售或已下修的公告。正式事件需在公告记录中另行维护；尚未实施的下修提议不会自动改变转股价。

## 数据时点、异常和并发

每只债券分别保存 `quote_at`、`stock_quote_at` 和 `fetched_at`。它们依次表示债券报价时点、正股报价时点及抓取时点，不能互相替代。基金持仓报告期、公告日和转股价生效日另存。

- 未来生效的转股价或未来报价不会进入较早数据日的计算。债股报价跨日、历史价用于较新数据日、持仓公告晚于数据日等情形会显示警告。
- TickFlow 百分比在适配边界由比值乘 100，字段缺失保持未知；全无有效债价时不改清单。
- 部分证券报价成功时，未返回的债股报价明确清空，不将旧股价装成新股价。行情时间倒退拒绝更新。
- 缺 Key、无权限、限流、格式错误及网络失败分别返回安全错误，旧清单继续保留。
- 请求行情时不占用数据锁；回写、研究保存、CSV 和 JSON 恢复都使用 `expected_revision` 做比较后替换。并发修改导致 409，需重新读取/预览，不静默覆盖。

详情编辑以打开时的清单 `revision` 作为固定试算和保存基准，界面发起试算时也提交该版本。若清单已更新，界面停止使用原试算结果并提示重新打开详情；服务端发现版本过期时返回 409，不会将另一版本的行情悄悄用于当前编辑稿。试算本身只读取同一份快照，不写盘、不改变版本。编辑内容变化后，先前试算结果失效，需要重新试算。

文件保存于本部署 `data_dir/custom/convertibles/snapshot.json`。读写大小上限为 32 MiB。沿用单后端进程的共享锁及原子文件替换，不支持多个独立服务进程共享同一目录并发写入。损坏文件、未知 schema 或 IO 错误均拒绝覆盖。

旧 schema 1 清单通过新增可选字段兼容读取。每次读取都会重算派生指标；恢复备份也不信任外部给定的衍生计算结果。恢复预览与最终保存使用一致的序列化大小口径，包含重算结果和新保存元数据，避免原文件未超限但实际写入超限。恢复不会导入密钥或更改软件配置。

自选、排除和显示列仅属于当前浏览器配置，不含在服务端研究备份中；浏览器存储受限时会退回当前会话并提示。这些偏好不改变原始研究清单。

## HTTP 接口

所有接口沿用原应用 `/api/` 全局认证，没有认证豁免或新增外部 Token 权限。

| 方法和路径 | 请求 / 用途 |
| --- | --- |
| `GET /api/ext/convertibles` | 当前完整快照，含研究记录及重算指标 |
| `GET /api/ext/convertibles/status` | 仅检查本地配置与已实现能力，不网络探测、不返回密钥 |
| `GET /api/ext/convertibles/template` | 完整标量 CSV 模板 |
| `POST /api/ext/convertibles/preview` | `{csv_text, as_of}`，不写入 |
| `POST /api/ext/convertibles/import` | `{csv_text, as_of, expected_revision, confirmed:true}` |
| `POST /api/ext/convertibles/refresh` | `{expected_revision}`，刷新现有清单报价 |
| `POST /api/ext/convertibles/{code}/analyze` | `{research, expected_revision?}`，只读试算；版本过期返回 409 |
| `PUT /api/ext/convertibles/{code}/research` | `{research, expected_revision}`，保存并重算 |
| `POST /api/ext/convertibles/restore/preview` | `{snapshot}`，校验完整 JSON 备份 |
| `POST /api/ext/convertibles/restore` | `{snapshot, expected_revision, confirmed:true}` |

成功写入均返回最新 `ConvertibleSnapshot`。研究输入的精确定义见 `backend/app/services/convertibles_models.py`；它限制现金流每类最多 30 条、公告最多 100 条，重复现金流/观察日期拒绝。

`analyze.expected_revision` 可选，以兼容已有调用方；当前界面始终传入打开详情时的版本。未传版本的调用使用请求开始时读取的当前快照，因此外部集成若需要与自己展示的数据严格对应，也应传入版本。研究保存、报价刷新、CSV 导入及备份恢复的 `expected_revision` 仍为必填。

## 二次开发与上游更新

独立模块位于 `backend/app/custom/convertibles.py`、`backend/app/services/convertibles_*.py` 和 `frontend/src/custom/convertibles/`。共享接线只在 `api.ts`、`queryKeys.ts` 追加。更换行情供应商应实现独立 `ConvertibleQuoteProvider`，并完成单位、时间、缺值及错误归一；不把债券强行塞入原股票的数据契约。

本分支与上游分开保留。上游更新需要在保留本分支提交后进行合并、解决冲突、重跑测试；正常 merge 不会主动删除本分支的独立扩展文件。不要用强制 reset、直接覆盖整个目录或安装上游原版包来代替合并。代码合并不能替代用户数据备份；更新前应导出 JSON。

此工作区的 upstream 抓取配置曾固定在 v0.3.11 标签；需要跟踪上游新主线时，应明确抓取所需分支或新标签，再审查合并内容，不能把一次 `git fetch upstream` 等同于已经取得最新主线。

## 验证

```bash
.venv/bin/python -m pytest tests/test_custom_funds.py tests/test_custom_convertibles.py tests/test_convertibles_math.py tests/test_convertibles_research_v2.py tests/test_convertibles_sources.py tests/test_extensions.py tests/test_fuyao_provider.py tests/test_fuyao_financial.py tests/test_openapi_contract.py -q

node node_modules/vitest/vitest.mjs run src/extensions/runtime.test.ts src/custom/funds src/custom/convertibles
node node_modules/typescript/bin/tsc -b
node node_modules/vite/bin/vite.js build
```
