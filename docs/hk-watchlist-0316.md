# 港股自选搜索修复（0.3.16）

## 问题与实现

0.3.15 的多资产港股行情列表能显示报价，但主界面“自选”搜索仍只检索本地 A 股、ETF 和指数缓存；00700 会误命中600700.SH等代码片段。行情列表按成交额限制500条，也不能用作港股证券搜索目录。

0.3.16 在原自选页接入独立港股搜索。输入00700、00700.HK、hk00700或腾讯名称可返回00700.HK及来源的真实证券名称“腾讯控股”。用户输入“腾讯科技”按品牌简称“腾讯”检索并说明别名，不修改真实证券名称。完整五位代码明确按港股处理；搜索失败时显示失败状态，不用A股代码片段替代。

搜索结果只确认名称和代码，不证明币种或价格。加入原有自选分组后，独立批量请求港股报价，带来源、实际报价时间、抓取时间和明确币种。研究数据涨跌幅的百分数在服务边界转换成自选的小数制。无报价不伪造价格；刷新失败保留上次有效报价。

复用原 ResearchMarketService：报价按 TickFlow → Fuyao → 公开补充源的能力顺序处理。名称检索优先TickFlow实际证券目录；Fuyao已公开港股能力为IPO，不能假设有全港股名称接口；不支持时使用腾讯、再新浪公开建议接口。此过程不登录或抓取集思录。

港股不进入A股历史K线、分时、竞价、扩展序列和技术指标链路；详情显示报价与来源，未接入指标保持未知。分组的A股统计不混入港元资产。自选enriched/SSE热路径只读取内存报价，不发网络请求。仍保留0.3.15的内容字体加大、侧栏字体不变及原有基金、转债、多资产模块。

## 参考来源及能力边界

| 来源 | 实际用途 | 边界 |
| --- | --- | --- |
| [stock-api](https://github.com/zhangxiangliang/stock-api) | 参考其腾讯smartbox、新浪港股搜索与公开行情实现 | MIT；直接调用公开服务，不运行整个代理；过滤港股普通证券GP，排除权证；响应仅解析文本，不执行脚本 |
| [Tushare hk_mins](https://tushare.pro/document/2?doc_id=304) | 港股历史分钟K，1/5/15/30/60分钟 | 需要单独港股历史分钟权限；入参是明确股票代码，不能解决名称搜索 |
| [Tushare hk_basic](https://tushare.pro/document/2?doc_id=191) | 全港股证券基础目录，可构建本地名称索引 | 文档要求至少2000积分；不是分钟或实时行情授权 |
| [Tushare hk_daily](https://tushare.pro/document/2?doc_id=192) | 港股历史日线 | 独立权限；非实时价格 |
| [Tushare rt_hk_k](https://tushare.pro/document/2?doc_id=383) | 港股实时日K快照 | 独立实时权限；不能从抓取时间虚构交易时间 |

本次没有添加或要求Tushare密钥，也没有把未验证的付费权限声称为可用。云端无个人API密钥，验证真实公开补充路径；主API优先级、单位、错误隔离另以契约测试覆盖。公开港股报价可能延迟约15分钟，不声称逐笔实时行情。

## 验证

新增搜索、报价、缓存与失败测试，并覆盖原自选分组和enriched链路。实际自选页集成测试验证搜索00700→加入指定分组→显示HKD报价，以及别名、详情、混合资产请求隔离和刷新失败保留旧报价。Windows云端安装测试在安装后的应用内运行同样搜索及自选报价接口，并在覆盖升级后重复执行，检查自选分组与其他测试资料保留。

本次为核心入口L3接线，未改变自选持久化schema。以后合并上游需重点复核kline搜索、自选enriched、Watchlist页面、前端API与查询键。
