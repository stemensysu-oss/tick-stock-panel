# 多资产研究工作台：架构与第一阶段

本扩展把套利股、封闭基金、ETF、现金管理、REITs、LOF、A/H 比价、T+0 QDII、分红、新股、债券和指数放进同一个研究入口。原有 `/funds` 基金研究和 `/convertibles` 可转债工作台继续使用原来的数据和接口。详细来源、权限和后续范围见[功能与数据源矩阵](multi-asset-source-matrix.md)。

**第一阶段是可用的导入研究工作台，不是已接通全市场行情的集思录替代服务。** 新增的 12 类模块均支持按字段模板导入、校验、浏览和导出；演示需要主动选择，记录为虚构数据。新增模块的 `live_status` 均为 `unavailable`。来源名称由用户填写，不会因为填写了交易所或供应商名称就变成“已核验 API”。

设计基线为用户分支 `feature/funds-convertibles` 的 `64eff881a98a69e0397c18e3918d1a654bf51b41`。截图用于确定信息分类和研究工作流，没有复制截图里的行情、账户持仓或集思录会员数据。截图中的“中概股私有化、港股私有化、港股供股权、A 股套利”归入套利股的事件类型；现金选择权、换股比例和供股权的专门估值仍属后续阶段。

## 1. 架构选择

采用仓库已经实现的 L2 扩展注册入口，避免修改主路由、应用生命周期、股票行情服务和原有研究模块。只在共享 API 客户端与查询键中追加工作台契约。

```text
backend/app/services/multi_asset_catalog.py
  字段、列、分类、说明、候选来源的单一注册表
               │
               ▼
CSV ──► MultiAssetService ──► data/multi_asset/workspace.json
        校验 / 派生计算          原子替换、版本检查
               │
        L2 后端路由扩展
        /api/multi-asset/*
               │
        api.ts + queryKeys.ts
               │
        L2 前端工作台扩展
        分类、筛选、详情、导入预览、导出

固定虚构样例 ──► 同一派生计算 ──► 只读演示快照
原有基金 / 可转债 ──► 原页面链接，保持原存储与数据源
```

分类注册表只描述研究字段和本阶段可用性，不取代核心 provider 能力矩阵。未来接实时源时，应先建立标准化数据集和 provider 能力，再在 service 层编排；页面不能直接请求供应商，也不能把基金净值、跨币种价格或债券条款塞进股票快照契约。

## 2. 本阶段范围

| 范围 | 本阶段行为 | 仍未实现 |
| --- | --- | --- |
| 统一入口 | 12 个分类，后端注册表决定字段和列；原基金、转债入口保留 | 无自动全市场证券目录 |
| 套利股 | 事件类型、日期、现金对价、来源链接；条件满足时计算对价相对现价空间 | 换股模型、供股权定价、失败概率、可执行交易路径 |
| 封闭基金 / ETF / LOF / QDII | 价格、单位净值、币种和日期；同日同币种溢价 | IOPV、篮子清单、申赎套利、自动限购状态 |
| A/H | 明确配对、两个价格、每港元人民币汇率；同日比较 | 自动配对、同步实时行情、实际换汇或跨市场交易 |
| 分红 / REITs | 明确现金分红期间、币种和口径，计算所填期间分派率 | 自动汇总公告、税后预测、资产估值模型 |
| 现金 / 债券 / 新股 / 指数 | 分类模板与可排序研究记录；保留利率、收益率等原始口径 | 收益率自动补造、申购下单、完整债券现金流模型 |
| 持仓 | 原有基金研究继续显示基金已披露持仓（依原数据源权限） | 个人多资产账户、券商同步、成本会计、跨币种盈亏 |

截图里的“持仓”既可能指个人组合，也可能指基金披露持仓。本阶段不把它们混为一项：个人持仓聚合待独立账户/成交/现金流水契约；现有持仓提醒也不等于组合会计。

## 3. 数据契约

每条导入记录至少包含 `code`、`name`、`currency`、`source_name` 和 `as_of`。`code` 按字符串保留前导零。可选公共字段为 `source_url`、`price`、`price_as_of`、`notes`；各分类额外字段由 `/catalog` 返回，下载模板与实际校验使用同一清单。

- `as_of` 是用户声明的资料基准日；价格日、净值日、汇率日、股息期间和事件日分别保存，不能拿导入时间充当行情时间。
- 价格是所填币种的每股、每份或报价单位原值。新工作台不自动复权、不自动换汇、不把净价转换成全价。债券报价单位、净价/全价以及指数点位等额外口径须在说明中明确。
- 百分数统一为 `2.5 = 2.5%`，与核心股票数据的部分小数比例契约不同。禁止按数值大小猜测转换。
- `income_per_10k` 是每万份收益金额；`rate_pct` 是百分数。七日年化、逆回购报价和每万份收益不自动相互换算。
- 未知值为空。非法日期、非有限数字、重复代码、未知字段和伪造状态字段会阻止写入；不把缺值当零。
- `source_name` / `source_url` 仅记录用户声明的出处。链接仅供查看，后端不会抓取该链接，更不会读取登录 Cookie。
- 导入和演示由快照明确区分，客户端不能导入 `computed` 或把记录声明成已核验实时 API。

字段级公告时间、完整交易规则、逐笔行情时间、发行人标识及自动化来源证据是后续 provider 契约的要求，不能认为当前 CSV 已经提供了这些能力。

### 派生指标

| 指标 | 计算 | 本阶段前提与含义 |
| --- | --- | --- |
| 净值溢价率 | `(price / nav - 1) × 100` | 价格、净值币种一致且 `price_as_of = nav_as_of = as_of`；NAV 不等于 IOPV |
| A/H 溢价率 | `(price / (h_price × fx_hkd_cny) - 1) × 100` | A 股 CNY、H 股 HKD；汇率为 CNY/HKD，三种价格/汇率日期均等于资料基准日 |
| 对价相对现价空间 | `(deal_price / price - 1) × 100` | 仅现金对价，同币种且同资料基准日；不含时间价值、失败风险、税费 |
| 所填期间股息率 | `dividend_per_share / price × 100` | 股息同币种、价格日等于资料基准日，期间已结束；不自动年化 |

`dividend_basis` 支持 `declared_period`（明确期间）或 `trailing_12_months`（完整滚动 12 个月，截至资料基准日）。滚动窗口由后端校验；不把一期分红自动乘四、不把预案当实施、不推断未来分红。当前字段没有单独税前/税后枚举，需在来源/备注中明示；跨税制比较前仍要人工核对。

任一计算前提缺失或不一致时，结果为空并显示原因。日期一致只消除明显的异日比较，不能证明两个市场在同一瞬间报价，也不能证明资料真实、证券可互换或申赎可完成。

## 4. 导入、存储与并发

完整 TSP 第一次进入默认显示导入模式。空清单直接解释未导入及未接通实时源，并提供模板和演示入口；错误状态不回退到演示数据。独立单文件预览默认展示醒目标注的虚构演示，用于体验分类、筛选、自选和详情；真实 CSV 导入导出与原模块须在完整 TSP 中使用。

导入流程为“选分类 → 下载/填写模板 → 校验预览 → 检查替换范围 → 确认保存”。一次导入只替换选定分类，保留其他分类及原基金、可转债数据。保存需要预览所依据的 `expected_revision`，所有分类共享一个工作区版本，发生并发更新时返回 409，用户重新读取后再次预览。

持久化由 service 负责，使用 `data/multi_asset/workspace.json` 和原子替换。读入失败、未知 schema 或不兼容字段时拒绝覆盖；演示与分类说明仍可独立查看。演示不写入真实清单。成功导入返回最新快照，前端更新对应查询缓存；分类和模式都进入查询键，避免切换后显示前一分类或演示记录。

CSV 支持 UTF-8/BOM、最大 2 MiB、每分类最多 2,000 条；合并存档最大 16 MiB。当前采用进程内锁，部署要求一个后端进程写入同一个数据目录；不要让多个实例或多个服务 worker 共享写入该文件。多进程写入需要后续增加跨进程锁或数据库事务。

导出提供当前分类的输入字段 CSV，派生字段在重新导入时重算。为防止电子表格把文本当成公式，公式前缀文本会添加单引号，重新导入时保留该字符；这是安全导出，不是逐字节无损备份。证券代码在电子表格软件里仍应选择文本列。导出不代表来源审核，也不是其他模块的数据备份。

## 5. HTTP 契约

所有路径使用主程序现有认证边界；未增加认证豁免。

| 方法 / 路径 | 请求与用途 |
| --- | --- |
| `GET /api/multi-asset/catalog` | 分类、字段、默认列、说明、候选来源、实际实时状态和原模块链接 |
| `GET /api/multi-asset/snapshot?category=etf&mode=imported` | 读取分类快照；`mode=demo` 读取只读虚构样例 |
| `GET /api/multi-asset/template?category=etf` | 下载本分类空 CSV 模板 |
| `POST /api/multi-asset/import/preview` | `{category, csv_text, expected_revision}`；校验和试算，不保存 |
| `POST /api/multi-asset/import` | 同上，附 `confirmed: true`；替换选定分类，返回新快照 |
| `GET /api/multi-asset/export?category=etf` | 导出当前分类的原始输入 CSV |

422 表示导入/参数错误；409 表示版本冲突；503 表示存储或扩展尚不可用。页面应分别提供修正、重读和重试方式，不能用空列表掩盖失败。

## 6. 后续接入顺序

1. **来源适配与日终数据。** 优先 ETF 目录/日线、净值、分红、新股等有明确文档的接口。逐个验证用户权限、证券覆盖、日期、单位、分页和失败行为，才能从“候选”改成“已验证”。公开网页是人工核对入口，不自动等价为稳定或获授权的机器接口。
2. **跨市场与事件资料。** 增加 A/H 配对和汇率时点，区分行情时间/公布时间；为私有化、现金选择权、换股与供股权建立带生效日的专门字段及计算测试。海外休市、条件未成就、资金占用和税费必须明确。
3. **规则与组合。** 根据基金合同和公告记录申赎、限购、转托管、结算和 T+0 资格。个人持仓先做用户主动导入，单独定义账户、数量、现金、成交、费用和外汇基准，再计算组合损益。第一阶段没有自动交易。

## 7. 上游升级与验证

保留上述基线和已有自定义提交；在有记录的功能分支上开发，不强制重置、不覆盖旧自定义目录。合并上游不可变版本前先运行 `scripts/upgrade_check.py`；合并后重新验证扩展发现、路由冲突隔离、历史基金/转债 API 和新工作台数据契约。共享冲突热点只有 `frontend/src/lib/api.ts`、`queryKeys.ts` 的增量接线以及发布文件。

适用验证包括：12 分类模板/样例一致性，缺值和日期/币种不匹配，百分比与万份收益隔离，股息窗口，导入失败不写入，跨分类保留，并发冲突，损坏文件/未来版本不覆盖，演示隔离，API 错误状态，前端分类/模式切换，以及实际构建。实际运行结果由交付记录单独记录；本设计文档不把待执行检查写成已通过。

本次工作不操作、卸载或安装用户电脑上现有 TSP。安装包或预览交付与实际部署是独立动作；新程序版本仍需保留原 `data/` 与外置配置。
