# 港股财报补充与分析输入

原港股分析只有日K、指标与关键价位，提示词固定写“财务、基本面与直接新闻均缺失”。所以即使公司已有公开财报，模型也收不到任何财务科目。现在三张报表独立读取并进入分析输入，技术图表不等待财报。

| 能力 | 本次实现 | 数据口径与剩余边界 |
| --- | --- | --- |
| 利润表 | 已接入 | 最新报告、上年同期间及最近年报，最多4期；收入、利润、EPS保持来源科目 |
| 资产负债表 | 已接入 | 期末资产、负债、权益及其他非空科目，不拿期末余额当期间流量 |
| 现金流量表 | 已接入 | 经营、投资、筹资现金流；已付股息是现金流科目，不是每股股息 |
| 披露日期 | 保持未知 | 公开整理源没有可靠公告日，不用报告期代替；不能用于历史时点回测 |
| PE/PB/股息率/市值 | 未核验 | 需独立报价、股本、TTM、汇率和同一时点口径，不能用港元股价直接除人民币EPS |
| 每股分红、除净日 | 尚未接入 | 下一阶段独立公司行动数据，不能由现金流已付股息反推 |
| 公告/新闻 | 提供腾讯官方报告核对链接 | 尚未自动提取正文，不能解释近期涨跌的具体事件原因 |
| 美日股财务 | 尚未接入 | 本次财报适配限定港股；美日股继续明确技术分析的输入边界 |

## 原有API优先

按每张报表分别尝试 TickFlow → 扶摇 → 东方财富公开补充源。TickFlow 使用现有SDK的真实 financials 方法，不猜接口。账户没有权限、返回为空、缺少明确港股财报币种与单位时不采用。当前SDK的A股财务schema不保证港股币种，不能擅自写为HKD。扶摇现有财务契约为A股，记录unsupported，不把港股代码发到A股接口。公开补充源只在前两者无法返回符合契约的数据时调用。上游异常只记录状态，不返回令牌或完整错误文本。

公开源由 AKShare 官方实现定位，TSP 使用固定域名、固定报表名称与有界请求，不导入整个 AKShare，不使用登录cookie、代理轮换或访问限制绕过。AKShare源码的开源许可不等于数据源的再分发授权；补充数据仅在用户运行时获取，不随程序打包分发。

## 币种、日期和单位

财报使用报告目录的CURRENCY，独立于行情币种。实测腾讯2026中报目录为人民币；另一张公开主要指标表的CURRENCY却为HKD，因此本次不采用那张指标表作汇率、估值依据。腾讯原始中报的人民币百万元金额与公开报表元金额抽样核对一致：收入401243百万元、归母盈利114115百万元、基本EPS12.639元/股。没有把中期数当全年或TTM。

所有记录校验标的、报告期、重复科目、有限数值及完整分页。未知/空值保持缺失，币种未知的报表不采用；分页超出500条时拒绝截断报表。每股科目单独标注元/股，其他货币科目为该币种元。报告期不是披露日，抓取时间不是披露日；缺失披露日必须在报告中说明。财报可重述，当前快照不用于历史回测。

## 接线与升级

新增GET `/api/stock-analysis/hk-fundamentals?symbol=00700.HK`。后端按标的和API身份摘要隔离30分钟缓存，最多32项，不写A股财务仓库；刷新导致资料覆盖下降时保留旧快照及其原抓取时间。前端通过公共API与集中查询键独立读取，显示加载、失败、未知字段、来源和期别。AI使用同一服务的报表，在技术部分后增加财务分析；数据不可用时逐张说明缺失，不一概声称已补齐所有基本面。

这属于L3最小核心接线加独立provider/service模块。旧报告、行情缓存、已有API Key、自选、基金转债自定义工作不迁移、不覆盖。后续合并上游需复核 stock_analysis API、公共API类型、查询键及共享港股分析组件。

## 本地验证（2026-10-24）

真实公开网络：00700.HK三张报表各4个报告期，最近2026-06-30分别27/53/31个非空科目，币种CNY。验证记录只保存来源、期别和条数，不保存整套公开报表到安装包。

HTTP分析路径使用标明的测试模型，断言实际财务字段进入模型输入且股价仍为HKD；覆盖币种未知、错标的、科目重复、截断、原有API优先、异常脱敏、刷新保留。界面测试检查财务表可见值、币种、披露日期未知及失败保留。原生Windows/Mac安装与真实联网验证由发布工作流另行执行，本文件不预先声称已通过云端。
